💡 為什麼要改?
目前頁面用 api.ipify.org 在瀏覽器端比對 IP 白名單,但整份 HTML 內容還是會先下載到瀏覽器,只是被 CSS 藏起來。關掉 JavaScript、看網頁原始碼、或用 curl 都能繞過,而且走 IPv6 的人會被誤擋。真正的存取控制必須擋在伺服器 / CDN 層。
架構圖: 訪客 ──► xxx.pages.dev ──► [ Cloudflare Access IP 閘門 ] ──► Cloudflare Pages(靜態報表) │ 白名單內 → 放行(不需登入) 白名單外 → 擋掉(edge 層,拿不到內容) ⚠ 同時必須關掉 GitHub Pages,否則 lard23chen.github.io/report/ 這個原始網址是後門
🔑 事前準備
一個 Cloudflare 免費帳號即可。全程不需要買網域(用免費的 *.pages.dev)。進 Zero Trust 第一次可能會要你填卡號做身分驗證,但免費方案 50 人以內不會扣款。

Part A · 部署到 Cloudflare Pages 你操作

把同一個 GitHub repo 接到 Cloudflare Pages,產生一個 .pages.dev 網址。這時網站還是公開的,先確認報表正常。

  1. 註冊 / 登入 Cloudflare Dashboard
  2. 左側 Workers & Pages → Create → Pages → Connect to Git
  3. 授權 GitHub,選 lard23chen/report 這個 repo
  4. 建置設定:
    • Framework preset → None
    • Build command → 留空
    • Build output directory → /(repo 根目錄就是網站根目錄)
  5. 按 Save and Deploy,完成後記下網址,例如 report-xxx.pages.dev
  6. 用瀏覽器開一次,確認報表正常顯示(此時任何人都看得到,正常)

Part B · 用 Access 設 IP 白名單 你操作

在 Cloudflare edge 層擋 IP。符合白名單的直接放行、不用登入,其他人一律擋掉。

  1. 左側進 Zero Trust(第一次要選免費方案;可能要填卡號驗證,不扣款)
  2. Access → Applications → Add an application → Self-hosted
  3. Application domain 填你的 Pages 網址:report-xxx.pages.dev
    ⚠️ 再加一條 *.report-xxx.pages.dev 一起保護 preview 部署(preview 會產生隨機子網域,不擋會有漏洞);或在 Pages 設定關掉 preview
  4. 新增 Policy:Action = Allow,Include 選 IP Ranges,填入下方 9 個 IP(每個加 /32)
    211.75.181.109/32 211.75.181.110/32 220.130.6.196/32 220.130.6.197/32 220.130.6.198/32 220.130.134.238/32 220.130.134.239/32 220.130.134.240/32 133.149.194.24/32
    只用 IP 這一個條件時,符合的 IP 直接放行、不需登入;其他人預設 deny。
  5. Save,然後用白名單外的網路(例如手機 4G)開一次,確認被擋才算成功

Part C · 關掉 GitHub Pages 後門 你操作

Access 擋得住之後,一定要把原本公開的 github.io 網址收掉,不然後門還開著。

  1. 確認 Part B 擋 IP 正常後,到 lard23chen/report → Settings → Pages → Source 設為 None(停用 GitHub Pages)
  2. (或改為把 repo 設 Private;Cloudflare Pages 已透過 GitHub App 有讀取權,不影響自動部署)
  3. 確認 lard23chen.github.io/report/ 已失效,對外唯一入口只剩 pages.dev

Part D · 清掉多餘的前端 guard 我幫你做

Access 上線後,HTML 裡那段 api.ipify.org 前端白名單就沒用了(也是 IPv6 誤擋的元凶)。這部分叫我做即可。

  1. 我寫反向腳本,移除所有 HTML + generator 裡的 guard(對應現有的 inject_ip_guard.js)
  2. 我補一份 REPORT_SPEC_ACCESS_CONTROL.md 記錄新架構,並更新總目錄
  3. 我 commit & push
⏱️ 順序很重要
請等 Part A~C 都完成、確認擋得住之後,再叫我執行 Part D 移除 guard。否則萬一 GitHub Pages 還沒關,就會變成完全不設防。
