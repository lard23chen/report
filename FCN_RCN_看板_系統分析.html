結構型商品追蹤看板 — 系統分析文件

版本 v1.0（已上線）・對象:個人 / 理專使用・涵蓋商品:FCN、RCN、DCN、CDRAN、SN 等結構型商品・對應規格文件：REPORT_SPEC_STRUCTURED_PRODUCTS.md

1. 系統概述

本系統目的是集中管理與追蹤持有中的結構型商品(FCN / RCN / DCN / CDRAN 等),取代目前用 Excel、紙本、理專個別提供表格的分散管理方式。核心價值：

  • 一眼看出目前資金狀況(投入本金、已領票息、已出場金額、報酬率)
  • 即時掌握每檔商品連結標的距離敲入(KI)/敲出(KO)障礙價的百分比,提早示警
  • 整合多家銀行(UBS、HSBC、玉山、星展等)的持倉於同一畫面
  • 保留已出場(KO / 到期)商品的歷史紀錄,方便回顧績效
參考來源:Instagram 影片示範的「FCN 交易看板」畫面架構(總覽卡片 + 追蹤表 + 觀察日 + 歷史紀錄),並比對你資料夾中實際的理專 RCN 表格、UBS/HSBC/玉山/星展對帳單、到期贖回通知信,將真實會用到的欄位一併納入。

2. 現況與痛點

現況問題
理專用 Excel / 手寫表格整理多檔 RCN(如你資料夾中的 理專整理RCN表格.jpeg)格式不一致、無法自動更新股價與障礙價距離,容易漏看即將敲出的商品
多家銀行(UBS / HSBC / 玉山 / 星展)各自對帳單格式不同需要人工彙整才能看到總資產與總曝險
到期 / 提前贖回通知以 email 形式個別寄送(如 Early Redemption、Maturity Redemption 通知信)沒有自動歸檔,事後要回頭查對績效很費時
觀察日、到期日分散在不同文件沒有集中的日曆提醒,容易錯過重要觀察日

3. 資料來源(輸入方式)

1
手動建檔
新增商品時輸入合約條款(標的、履約價、KI/KO、票息、到期日)
2
對帳單匯入
解析 UBS / HSBC / 玉山 / 星展 PDF 對帳單,擷取持倉與金額
3
Email 通知解析
讀取「Early/Maturity Redemption」通知信,自動登記出場事件與 ISIN
4
股價 API
每日抓取連結標的最新價格,自動計算距離障礙價 %

實際上線後採「管理員手動建檔（前端編輯模式）＋ 對帳單資料人工擷取後一次性匯入資料庫」的方式：27 檔商品中，8 檔 UBS/CAKE RCN/DCN 有完整標的/履約價/障礙價，3 檔 UBS CDRAN 用 conditions 記錄信用/利率/匯率條件，其餘 13 檔（HSBC 7、玉山 3、星展 3）僅有金額/到期日等基本資料，待補齊申購確認書後升級。PDF/Email 全自動解析目前尚未實作，列為後續階段。

4.3 商品追蹤總覽表（核心功能）

每一列代表一檔商品，一檔商品可能連結多個標的（worst-of 一籃子股票，如你 RCN 表格中的 NVDA/TSMC 雙標的）：

欄位說明
商品類型FCN / RCN / DCN / CDRAN / SN
ISIN商品識別碼（部分商品尚無 ISIN）
發行商 / 託管銀行如 BARC、BNP、SG、GS、UBS / UBS、HSBC、玉山證券、星展
金額幣別 + 本金
連結標的可多檔（worst-of），各自履約價(strike)；CDRAN 等無股權標的商品則為空，改用「額外連動條件」
距 KI % / 距 KO %取 worst-of 中距離敲入(KI)最小的標的計算風險；KO 僅作為提前出場提示，不計入風險分數
額外連動條件CDRAN 等商品的利率(CMS)、信用事件、匯率條件，存於 conditions
下一觀察日 / 到期日到期日僅在真正確定時才填寫，多數商品以下次觀察日（fixings）呈現
狀態燈號安全 警戒 高風險 灰色「不適用」（無股權標的或資料不全）
風險評分系統自動計算（見第 7 節），無股權標的商品回傳 null

4.4 已出場歷史紀錄

記錄每一檔已經 KO 或到期出場的商品：出場日期、出場原因、實現損益、持有天數。

4.5 提醒通知

  • 觀察日前 N 天提醒
  • 標的價格接近 KO/KI 障礙時提醒（如距離 < 5%）

6. 資料模型（已實作）

Collection關鍵欄位
Structured_Products（商品主檔，一檔商品一筆文件）_id, productType(FCN/RCN/DCN/CDRAN/SN), isin, issuer, custodianBank, currency, principalAmount, couponRate, issueDate, maturityDate, status, underlyings[]（內嵌：ticker/strikePrice/koBarrierPct/kiBarrierPct/lastPrice/lastPriceDate）, conditions[]（內嵌：type/description/threshold）, fixings[]（內嵌：date/isFinal/result）, person, note
Structured_Products_Events（現金流/事件紀錄，一筆事件一筆文件）_id, productId(ref), date, type(申購/配息/提前贖回KO/到期贖回), amount, note

實作採 MongoDB 內嵌陣列（underlyings/conditions/fixings 皆為商品主檔內的子陣列），而非原草稿設想的多張正規化資料表；僅現金流事件獨立成另一個 collection。詳細欄位定義請見 REPORT_SPEC_STRUCTURED_PRODUCTS.md。

7. 風險評分邏輯（已實作）

因子權重說明
距離 KI（敲入）障礙價 %40%越接近或已跌破 KI 分數越高（風險越高）；worst-of 取所有標的中距 KI 最小者代表整檔商品
剩餘天數至下次觀察日20%越接近觀察日，警示等級提高
標的近 20 日年化波動度25%日報酬標準差 × √252 × 100
是否曾經收盤跌破 KI15%MVP 假設美式障礙，曾經穿價的標的列為需持續關注

與草稿版的差異：風險主要來自 KI（下方保護障礙），並非 KO。KO（提前贖回）對投資人是正向事件，僅作為「即將提前出場」提示，不計入風險分數（v0.1 草稿原先誤將 KO 列為風險因子，已於實作階段修正）。

燈號規則（已實作）：安全 風險分數 < 30　警戒 30–60　高風險 > 60。無股權標的商品（CDRAN 及資料不全的 SN/FCN）不套用此模型，直接回傳灰色「不適用」。

8. 技術架構（已採用）

層實際方案
前端純 HTML/CSS/JavaScript（無框架），部署於 GitHub Pages（Structured_Products.html）
後端 / APINode.js + Express，Vercel Serverless Functions（structured_products_api.js）
資料庫MongoDB Atlas（沿用既有 cluster，新增 Structured_Products / Structured_Products_Events collection）
股價資料Yahoo Finance chart API（/v8/finance/chart/SYMBOL），即時抓取近 3 個月收盤價計算風險
PDF / Email 解析目前為人工用 pdfplumber 擷取對帳單數字後一次性匯入，尚未做成自動化排程

與草稿 v0.1 設想的 React + PostgreSQL 方案不同，考量個人使用規模與現有 report repo 慣例，改採更輕量的純 HTML 前端 + Serverless + MongoDB 架構，與同 repo 內其他追蹤頁面（如 Stock_Portfolio.html）風格一致。
