結構型商品追蹤看板 — 系統分析文件

版本 v0.1（草稿）・對象:個人 / 理專使用・涵蓋商品:FCN、RCN、DCN、CDRAN 等結構型商品

1. 系統概述

本系統目的是集中管理與追蹤持有中的結構型商品(FCN / RCN / DCN / CDRAN 等),取代目前用 Excel、紙本、理專個別提供表格的分散管理方式。核心價值：

  • 一眼看出目前資金狀況(投入本金、已領票息、已出場金額、報酬率)
  • 即時掌握每檔商品連結標的距離敲入(KI)/敲出(KO)障礙價的百分比,提早示警
  • 整合多家銀行(UBS、HSBC、玉山、星展等)的持倉於同一畫面
  • 保留已出場(KO / 到期)商品的歷史紀錄,方便回顧績效
參考來源:Instagram 影片示範的「FCN 交易看板」畫面架構(總覽卡片 + 追蹤表 + 觀察日 + 歷史紀錄),並比對你資料夾中實際的理專 RCN 表格、UBS/HSBC/玉山/星展對帳單、到期贖回通知信,將真實會用到的欄位一併納入。

2. 現況與痛點

現況問題
理專用 Excel / 手寫表格整理多檔 RCN(如你資料夾中的 理專整理RCN表格.jpeg)格式不一致、無法自動更新股價與障礙價距離,容易漏看即將敲出的商品
多家銀行(UBS / HSBC / 玉山 / 星展)各自對帳單格式不同需要人工彙整才能看到總資產與總曝險
到期 / 提前贖回通知以 email 形式個別寄送(如 Early Redemption、Maturity Redemption 通知信)沒有自動歸檔,事後要回頭查對績效很費時
觀察日、到期日分散在不同文件沒有集中的日曆提醒,容易錯過重要觀察日

3. 資料來源(輸入方式)

1
手動建檔
新增商品時輸入合約條款(標的、履約價、KI/KO、票息、到期日)
2
對帳單匯入
解析 UBS / HSBC / 玉山 / 星展 PDF 對帳單,擷取持倉與金額
3
Email 通知解析
讀取「Early/Maturity Redemption」通知信,自動登記出場事件與 ISIN
4
股價 API
每日抓取連結標的最新價格,自動計算距離障礙價 %

MVP 階段建議先做「手動建檔 + Excel/CSV 匯入」，PDF/Email 自動解析可以列為第二階段（需要針對每家銀行對帳單格式個別寫解析規則）。

4.3 商品追蹤總覽表（核心功能）

每一列代表一檔商品，一檔商品可能連結多個標的（worst-of 一籃子股票，如你 RCN 表格中的 NVDA/TSMC 雙標的）：

欄位說明
商品類型FCN / RCN / DCN / CDRAN
發行商如 BNP、SG、GS、UBS
託管銀行UBS / HSBC / 玉山 / 星展
連結標的可多檔（worst-of），各自履約價(strike)
KI 障礙價 / 距離%入場價與目前價的差距
KO 障礙價 / 距離%出場價與目前價的差距
額外連動條件如利率(CMS)、信用事件、匯率條件
票息 / 配息頻率
下一觀察日 / 到期日
狀態燈號安全 接近障礙 高風險
風險評分系統自動計算（見第 7 節）

4.4 已出場歷史紀錄

記錄每一檔已經 KO 或到期出場的商品：出場日期、出場原因、實現損益、持有天數。

4.5 提醒通知

  • 觀察日前 N 天提醒
  • 標的價格接近 KO/KI 障礙時提醒（如距離 < 5%）

6. 資料模型（ER 結構建議）

資料表關鍵欄位
products（商品主檔）id, product_type(FCN/RCN/DCN/CDRAN), isin, issuer, custodian_bank, currency, principal_amount, coupon_rate, issue_date, maturity_date, status
underlyings（連結標的，一檔商品對多筆）id, product_id(FK), ticker, strike_price, ki_barrier_pct, ko_barrier_pct, last_price, last_price_date
conditions（額外連動條件，如 CMS 利率、信用事件）id, product_id(FK), condition_type, description, threshold
fixings（觀察日排程）id, product_id(FK), fixing_date, is_final, result
cashflows（出入金 / 配息紀錄）id, product_id(FK), date, type(申購/配息/提前贖回/到期贖回), amount
events_log（已出場歷史）id, product_id(FK), event_date, event_type(KO/到期/提前贖回), realized_pnl, source(如來自哪封通知信)

7. 風險評分邏輯（建議，需與你確認公式）

因子權重（建議）說明
距離 KO 障礙價 %40%越接近障礙價分數越低（風險越高）
剩餘天數至下次觀察日20%越接近觀察日且逼近障礙，警示等級提高
標的近期波動度25%可用近 20 日歷史波動率估算
是否曾經穿價15%曾經穿過障礙價的標的列為需持續關注

燈號規則（範例，可調整）：安全 距障礙價 > 15%　警戒 5%–15%　高風險 < 5%

8. 技術架構建議

層建議方案
前端React + Tailwind CSS + Recharts / ECharts（依此文件的 wireframe 實作）
後端 / APINode.js 或 Python(FastAPI)，負責計算風險分數、彙整資料
資料庫PostgreSQL / SQLite（個人使用可先用 SQLite）
股價資料yfinance 或券商 API，每日排程更新
PDF / Email 解析（第二階段）Python + pdfplumber 解析對帳單；email 用 IMAP 抓信 + 規則解析 ISIN 與贖回類型
MVP 替代方案若不想寫程式，可先用 Google Sheets + Apps Script 做出九成功能
